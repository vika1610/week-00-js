# Конспект · Неделя 0 · День 3

Деструктуризация → spread и rest → методы массивов.
Все примеры можно запускать в консоли браузера (F12 → Console).

> ⚠️ Отмечены **подводные камни** — места, где чаще всего ошибаются.

Это один из самых важных дней для Vue: в коде на Vue `map`, `filter`, spread и деструктуризация встречаются буквально в каждом файле.

---

## Часть 1. Деструктуризация

**Деструктуризация** — короткий способ «распаковать» значения из объекта или массива в отдельные переменные.

### Деструктуризация объекта

Без неё:

```js
const movie = { title: 'Интерстеллар', year: 2014, rating: 8.7 }

const title = movie.title
const year = movie.year
```

С ней:

```js
const { title, year } = movie
title // 'Интерстеллар'
year  // 2014
```

Слева в фигурных скобках перечислены **имена свойств**. JS находит в объекте свойства с такими именами и кладёт их значения в одноимённые переменные. Порядок не важен, важны имена.

### Переименование

Если хочется, чтобы переменная называлась иначе, чем свойство:

```js
const { title: movieName } = movie
movieName // 'Интерстеллар'
title     // ✗ ReferenceError — переменной title нет!
```

⚠️ Запись `title: movieName` читается как «свойство `title` положи в переменную `movieName`». Её легко перепутать с объектом `{ ключ: значение }`, где всё наоборот.

### Значения по умолчанию

Как у параметров функции из дня 1:

```js
const { director = 'неизвестен' } = movie
director // 'неизвестен' — такого свойства нет, взялось значение по умолчанию
```

⚠️ Значение по умолчанию срабатывает только для `undefined`. Если там `null`, `0` или `''`, возьмётся именно оно.

### Остаток свойств

```js
const { title, ...rest } = movie
rest // { year: 2014, rating: 8.7 } — всё, кроме title
```

Удобный способ «убрать» из объекта ненужные свойства. Эта запись уже встречалась в подсказке к задаче недели 2 про пароли.

### Вложенная деструктуризация

```js
const user = { name: 'Аня', address: { city: 'Казань' } }

const { address: { city } } = user
city // 'Казань'
```

Можно, но с глубокой вложенностью код быстро становится нечитаемым. Используй в меру.

### Деструктуризация массива

Здесь важен **порядок**, а не имена:

```js
const colors = ['красный', 'зелёный', 'синий']

const [first, second] = colors
first  // 'красный'
second // 'зелёный'

const [, , third] = colors   // пропустить элементы — запятыми
third  // 'синий'
```

Классический трюк — поменять две переменные местами:

```js
let a = 1
let b = 2
;[a, b] = [b, a]
a // 2
b // 1
```

> Точка с запятой перед `[` нужна, если вы пишете без `;` в конце строк. Иначе JS может склеить эту строку с предыдущей.

### Деструктуризация в параметрах функции ⭐

Самое частое применение, и во Vue в том числе:

```js
// без деструктуризации
function describe(movie) {
  return `${movie.title} (${movie.year})`
}

// с деструктуризацией — сразу видно, какие поля нужны функции
function describe({ title, year }) {
  return `${title} (${year})`
}

describe(movie) // 'Интерстеллар (2014)'
```

То же со стрелочной функцией: `const describe = ({ title, year }) => ...`.

### ⚠️ Деструктуризация `undefined` и `null` — ошибка

```js
const { name } = undefined // ✗ TypeError: Cannot destructure property 'name' of 'undefined'
```

Чаще всего это значит, что в функцию не передали объект. Защита — значение по умолчанию у параметра:

```js
function greet({ name } = {}) {
  return `Привет, ${name ?? 'гость'}`
}
greet() // 'Привет, гость'
```

> `??` — оператор «если слева `null` или `undefined`, то взять правое». Встретится ещё не раз.

## Часть 2. Spread и rest — три точки `...`

Выглядят одинаково, а делают противоположное:

| | Где стоит | Что делает |
|---|---|---|
| **spread** («разложить») | при **создании** массива/объекта или при **вызове** функции | раскладывает элементы наружу |
| **rest** («собрать остаток») | при **объявлении** параметров или в деструктуризации | собирает элементы в массив/объект |

Как отличить: `...` **слева** от `=` или в скобках объявления функции — это rest. Во всех остальных местах — spread.

### Spread для массивов

```js
const fruits = ['яблоко', 'груша']
const veggies = ['морковь']

const food = [...fruits, ...veggies]   // ['яблоко', 'груша', 'морковь']
const more = [...fruits, 'банан']      // ['яблоко', 'груша', 'банан']
const copy = [...fruits]               // новый массив с теми же элементами

copy === fruits // false — это другой массив
```

Spread в вызове функции:

```js
const nums = [5, 1, 9]
Math.max(...nums) // 9 — то же, что Math.max(5, 1, 9)
Math.max(nums)    // NaN — функция получила один аргумент-массив
```

### Spread для объектов

```js
const user = { name: 'Аня', age: 25 }

const copy = { ...user }                  // поверхностная копия
const older = { ...user, age: 26 }        // копия с изменённым age
const withCity = { ...user, city: 'Казань' } // копия с новым свойством

user.age // 25 — оригинал не тронут
```

Последний пример — главный способ «изменить» объект, **не меняя оригинал**. Во Vue и Pinia он встречается постоянно.

### ⚠️ Порядок имеет значение

Если ключ встречается несколько раз, побеждает **последний**:

```js
{ ...user, age: 26 } // { name: 'Аня', age: 26 }
{ age: 26, ...user } // { name: 'Аня', age: 25 } — age перезаписан из user!
```

Подумай, как это поможет в задаче `mergeSettings`, где «пользовательские настройки важнее».

### ⚠️ Spread копирует поверхностно

Это то же самое, что `Object.assign({}, obj)` из дня 2: вложенные объекты остаются **общими**.

```js
const original = { name: 'Аня', address: { city: 'Москва' } }
const copy = { ...original }

copy.address.city = 'Казань'
original.address.city // 'Казань' 😱
```

Если нужно изменить вложенный объект, его тоже разворачивают:

```js
const moved = { ...original, address: { ...original.address, city: 'Казань' } }
```

### Rest в параметрах функции

Собирает **все оставшиеся** аргументы в настоящий массив:

```js
function logAll(label, ...items) {
  return `${label}: ${items.join(', ')}`
}

logAll('Покупки', 'хлеб', 'молоко', 'сыр') // 'Покупки: хлеб, молоко, сыр'
logAll('Пусто')                           // 'Пусто: ' — items = []
```

⚠️ Rest-параметр должен быть **последним**: `function f(...a, b)` — синтаксическая ошибка.

⚠️ Если аргументов нет, rest — **пустой массив**, а не `undefined`. Это удобно: с ним можно сразу работать.

### Rest в деструктуризации

```js
const [winner, ...others] = ['Аня', 'Оля', 'Катя']
winner // 'Аня'
others // ['Оля', 'Катя']
```

## Часть 3. Методы массивов

### Главная идея: не пиши цикл — опиши, что нужно

Вместо цикла `for` с ручным счётчиком у массивов есть методы. Ты передаёшь в них **функцию** (обычно стрелочную), и метод сам вызывает её для каждого элемента.

Функция получает до трёх аргументов: `(элемент, индекс, весьМассив)`. Обычно нужен только первый.

Данные для примеров:

```js
const students = [
  { name: 'Аня', grade: 5, city: 'Москва' },
  { name: 'Борис', grade: 3, city: 'Казань' },
  { name: 'Вера', grade: 4, city: 'Москва' },
  { name: 'Глеб', grade: 2, city: 'Сочи' },
]
```

### Как выбрать метод — главная таблица

| Что нужно получить | Метод | Возвращает |
|---|---|---|
| новый массив **той же длины**, но преобразованный | `map` | массив |
| **часть** элементов по условию | `filter` | массив (может быть пустым) |
| **один** элемент по условию | `find` | элемент или `undefined` |
| **индекс** элемента | `findIndex` | число или `-1` |
| «есть ли **хоть один**?» | `some` | `true` / `false` |
| «**все** ли подходят?» | `every` | `true` / `false` |
| **одно значение** из всех (сумма, максимум, объект) | `reduce` | что угодно |
| упорядочить | `sort` | тот же массив ⚠️ |
| просто сделать что-то для каждого | `forEach` | `undefined` |

Перед тем как писать код, задай себе вопрос: **«Что я хочу получить на выходе?»** Таблица подскажет метод.

---

### `map` — преобразовать каждый элемент

```js
const names = students.map((s) => s.name)
// ['Аня', 'Борис', 'Вера', 'Глеб']

const labels = students.map((s) => `${s.name}: ${s.grade}`)
// ['Аня: 5', 'Борис: 3', ...]
```

Результат **всегда той же длины**, что и исходный массив. Исходный массив не меняется.

⚠️ **Самая частая ошибка — фигурные скобки без `return`:**

```js
students.map((s) => { s.name })        // [undefined, undefined, ...]
students.map((s) => { return s.name }) // ✓
students.map((s) => s.name)            // ✓
```

Это та же ловушка, что в дне 1: с `{ }` нужен `return`.

⚠️ **Возврат объекта из стрелки — оберни в круглые скобки:**

```js
students.map((s) => { name: s.name })   // [undefined, ...] — {} принят за тело функции!
students.map((s) => ({ name: s.name })) // ✓ [{ name: 'Аня' }, ...]
```

### `filter` — оставить подходящие

Функция возвращает `true` (оставить) или `false` (выкинуть):

```js
const good = students.filter((s) => s.grade >= 4)
// [Аня, Вера]

const fromMoscow = students.filter((s) => s.city === 'Москва')
```

⚠️ `filter` **всегда** возвращает массив, даже если подошёл один элемент (`[{...}]`) или ни одного (`[]`). Если нужен сам элемент — это `find`.

⚠️ Обрати внимание на границы условий: `>` и `>=` дают разный результат на «пограничном» значении. Тесты часто проверяют именно его.

### `find` и `findIndex` — найти один

```js
students.find((s) => s.name === 'Вера')
// { name: 'Вера', grade: 4, city: 'Москва' }

students.find((s) => s.name === 'Дима')
// undefined — не нашёл

students.findIndex((s) => s.name === 'Вера') // 2
students.findIndex((s) => s.name === 'Дима') // -1
```

`find` останавливается на **первом** подходящем элементе.

⚠️ `find` возвращает **сам объект** из массива, а не копию. Если его изменить, изменится и элемент массива. Это ссылки из дня 2.

### `some` и `every` — да или нет

```js
students.some((s) => s.grade === 2)  // true — хотя бы один двоечник есть
students.every((s) => s.grade >= 3)  // false — не все троечники и выше
```

⚠️ На пустом массиве: `[].some(...)` → `false`, `[].every(...)` → `true` («все ноль элементов подходят»). Звучит странно, но так устроена логика.

### `includes` — есть ли значение

Для простых значений — без функции:

```js
['Москва', 'Казань'].includes('Казань') // true
```

⚠️ Для объектов `includes` сравнивает **ссылки**, как `===`, поэтому `students.includes({ name: 'Аня', ... })` даст `false`. Для поиска объекта по полю — `some` или `find`.

### `reduce` — свернуть массив в одно значение

Самый мощный и самый непривычный метод. Он проходит по массиву и **накапливает** результат:

```js
const sum = students.reduce((acc, s) => acc + s.grade, 0)
// 14
```

- `acc` (аккумулятор) — накопленный результат;
- `s` — текущий элемент;
- `0` — **начальное** значение `acc`;
- то, что возвращает функция, становится новым `acc` для следующего шага.

Пошагово:

| Шаг | `acc` до | `s.grade` | вернули (новый `acc`) |
|---|---|---|---|
| 1 | 0 | 5 | 5 |
| 2 | 5 | 3 | 8 |
| 3 | 8 | 4 | 12 |
| 4 | 12 | 2 | **14** ← результат |

Аккумулятор может быть чем угодно, хоть объектом:

```js
const byCity = students.reduce((acc, s) => {
  acc[s.city] = (acc[s.city] ?? 0) + 1
  return acc
}, {})
// { 'Москва': 2, 'Казань': 1, 'Сочи': 1 }
```

⚠️ **Всегда передавай начальное значение.** Без него `acc` на первом шаге — это первый **элемент** массива, то есть целый объект студента, и `объект + число` превратится в строку-кашу. А на пустом массиве без начального значения будет ошибка `Reduce of empty array with no initial value`.

⚠️ Функция обязана **вернуть** `acc`. Если в теле с `{ }` забыть `return`, на следующем шаге `acc` станет `undefined`.

### `sort` — сортировка ⚠️⚠️

В `sort` сразу три ловушки.

**⚠️ 1. `sort` меняет исходный массив.** Он не создаёт новый, а переставляет элементы на месте и возвращает тот же массив:

```js
const nums = [3, 1, 2]
const sorted = nums.sort()
nums           // [1, 2, 3] — оригинал изменился!
sorted === nums // true
```

Если оригинал нужно сохранить, сначала сделай **копию**. Как скопировать массив — смотри часть 2.

**⚠️ 2. Без функции `sort` сравнивает как строки:**

```js
[10, 9, 100].sort() // [10, 100, 9] 😱 — потому что '1' < '9' в строках
```

**⚠️ 3. Для чисел нужна функция сравнения.** Она получает два элемента `a` и `b` и возвращает число:

- **отрицательное** — `a` должен идти раньше `b`;
- **положительное** — `b` раньше `a`;
- **ноль** — порядок не важен.

Трюк: разность `a - b` как раз даёт нужный знак.

```js
[10, 9, 100].sort((a, b) => a - b) // [9, 10, 100] — по возрастанию
[10, 9, 100].sort((a, b) => b - a) // [100, 10, 9] — по убыванию
```

Для объектов сравнивай нужное поле:

```js
const ages = [{ name: 'Аня', age: 30 }, { name: 'Оля', age: 22 }]
ages.sort((a, b) => a.age - b.age) // сначала Оля (22), потом Аня (30)
```

Строки по алфавиту (с учётом русского языка):

```js
['Вера', 'Аня', 'Борис'].sort((a, b) => a.localeCompare(b)) // ['Аня', 'Борис', 'Вера']
```

### `forEach` — просто пройтись

```js
students.forEach((s) => console.log(s.name))
```

⚠️ `forEach` **ничего не возвращает** (`undefined`). Если нужен новый массив — это `map` или `filter`. Вопрос «Чем `map` отличается от `forEach`?» есть в «Проверь себя» конца недели 🙂

### Цепочки методов

`map` и `filter` возвращают массивы, поэтому их можно вызывать друг за другом:

```js
const goodNames = students
  .filter((s) => s.grade >= 4)
  .map((s) => s.name)
// ['Аня', 'Вера']
```

Читается сверху вниз как рецепт: «отфильтруй хороших, возьми имена».

### ⚠️ Какие методы меняют массив, а какие нет

| ❌ Меняют исходный массив | ✅ Создают новый |
|---|---|
| `push`, `pop`, `shift`, `unshift` | `map`, `filter` |
| `splice` | `slice`, `concat` |
| `sort`, `reverse` | `[...arr]` |

Это продолжение вчерашней темы «меняет объект или создаёт новый». Во Vue очень важно понимать, какой метод что делает.

## Шпаргалка

| Тема | Запомнить |
|---|---|
| `const { a, b } = obj` | достать свойства по **именам** |
| `const [x, y] = arr` | достать элементы по **порядку** |
| `{ a: newName }` | переименование при деструктуризации |
| `function f({ a, b })` | деструктуризация прямо в параметрах |
| `[...arr]`, `{ ...obj }` | spread: поверхностная копия |
| `{ ...obj, key: value }` | копия с изменением; побеждает последний ключ |
| `function f(...args)` | rest: все аргументы в массив |
| `map` | то же количество, преобразованные элементы |
| `filter` | меньше или столько же; **всегда массив** |
| `find` | один элемент или `undefined` |
| `some` / `every` | `true` / `false` |
| `reduce` | одно значение; **не забудь начальное** |
| `sort` | **меняет оригинал**, числам нужна `(a, b) => a - b` |
| `() => ({ ... })` | вернуть объект из стрелки — в круглых скобках |
