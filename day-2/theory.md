## Часть 1. Области видимости

### Что такое область видимости

**Область видимости** — участок кода, где переменная «существует» и доступна по имени.

Для `let` и `const` границы области задают фигурные скобки `{ }`: блок `if`, тело цикла, тело функции или просто голые `{ }`.

```js
{
  const message = 'внутри'
  console.log(message) // 'внутри'
}
console.log(message)   // ✗ ReferenceError
```

### Правило «изнутри видно наружу»

Вложенный код видит переменные внешних блоков. Внешний код вложенные переменные не видит.

```js
const a = 1
function outer() {
  const b = 2
  function inner() {
    const c = 3
    console.log(a, b, c) // 1 2 3 — видно всё снаружи
  }
  inner()
  console.log(c)         // ✗ ReferenceError — c живёт только в inner
}
```

Когда JS встречает имя переменной, он ищет её **цепочкой**: сначала в текущем блоке, потом во внешнем, потом ещё выше и так до глобальной области. Нашёл — берёт. Не нашёл нигде — `ReferenceError`.

### ⚠️ Затенение (shadowing)

Если внутри объявить переменную с тем же именем, внешняя «закроется»:

```js
const color = 'красный'
function paint() {
  const color = 'синий'   // своя переменная, внешняя не тронута
  return color
}
paint()  // 'синий'
color    // 'красный'
```

Это не ошибка, но легко запутаться. Используй разные имена, если это не задумано специально.

### ⚠️ Нельзя обратиться к `let` / `const` до объявления

```js
console.log(price) // ✗ ReferenceError: Cannot access 'price' before initialization
const price = 100
```

Участок от начала блока до строки объявления называют «мёртвой зоной» (temporal dead zone).

### ⚠️ `var` — почему его не используют

`var` устроен по старым правилам:

1. **Игнорирует блоки**, видна во всей функции:
   ```js
   if (true) {
     var leak = 'утекло'
   }
   leak // 'утекло' — с let была бы ошибка
   ```
2. **«Поднимается»**: до объявления она равна `undefined`, ошибки нет:
   ```js
   console.log(x) // undefined — тихо, без ошибки
   var x = 5
   ```
3. Можно объявить дважды, и никто не предупредит.

Вывод: пиши `const`, а если значение меняется — `let`. `var` встретится только в старом коде.

### ⚠️ Случайные глобальные переменные

Если забыть `let` / `const`, в нестрогом режиме создастся **глобальная** переменная:

```js
function oops() {
  total = 10 // забыли const — total стала глобальной
}
```

В модулях (а все наши файлы — модули) действует строгий режим, и тут будет ошибка. Это хорошо: ошибка лучше тихого бага.

## Часть 2. Замыкания

### Функции — тоже значения

Функцию можно положить в переменную, передать как аргумент или вернуть из другой функции:

```js
const sayHi = () => 'Привет'
function callTwice(fn) {
  return fn() + ' ' + fn()
}
callTwice(sayHi) // 'Привет Привет'
```

### Что такое замыкание

**Замыкание** — функция вместе с переменными того места, где она была **создана**. Функция «помнит» своё окружение, даже когда внешняя функция давно закончила работу.

```js
function makeMultiplier(factor) {
  return (n) => n * factor
}

const double = makeMultiplier(2)
const triple = makeMultiplier(3)

double(5) // 10
triple(5) // 15
```

Как это работает:

1. Вызов `makeMultiplier(2)` создаёт **новое окружение**, где `factor = 2`.
2. Внутри создаётся стрелочная функция. Она получает «невидимую ссылку» на это окружение.
3. `makeMultiplier` завершается, но окружение не исчезает: на него всё ещё ссылается `double`.
4. Вызов `makeMultiplier(3)` создаёт **другое** окружение с `factor = 3`, независимое от первого.

### Замыкание с изменяемым состоянием

Внутренняя функция может не только читать, но и **менять** запомненную переменную. Переменная живёт между вызовами:

```js
function makePlaylist() {
  const songs = []
  return (song) => {
    songs.push(song)
    return `В плейлисте ${songs.length} песен`
  }
}

const add = makePlaylist()
add('Кино')     // 'В плейлисте 1 песен'
add('Сплин')    // 'В плейлисте 2 песен'
```

До `songs` снаружи не добраться никак: её можно менять только через `add`. Так в JS делают **приватные данные**.

Внутренних функций может быть **несколько**, если вернуть их в объекте. Тогда все они разделяют **одно** окружение:

```js
function makeWallet() {
  let money = 0
  return {
    put(sum) { money += sum },
    show() { return `${money} ₽` },
  }
}

const wallet = makeWallet()
wallet.put(100)
wallet.put(50)
wallet.show()  // '150 ₽'
wallet.money   // undefined — денег «снаружи» не видно
```

### Где замыкания встречаются на практике

- обработчики событий: функция-обработчик помнит переменные, которые были рядом при её создании;
- `setTimeout` и `setInterval`;
- **во Vue почти везде**: `<script setup>` и композаблы (неделя 4) целиком построены на замыканиях.

### ⚠️ Замыкание помнит переменную, а не значение

Функция видит **текущее** значение переменной на момент вызова, а не то, что было при создании:

```js
let name = 'Аня'
const greet = () => `Привет, ${name}`
name = 'Оля'
greet() // 'Привет, Оля' — а не 'Аня'!
```

### ⚠️ Каждый вызов внешней функции — новая память

```js
const a = makeWallet()
const b = makeWallet()
a.put(100)
b.show() // '0 ₽' — у b свой кошелёк
```

Частая ошибка: ожидать, что два созданных объекта делят одно состояние. Или наоборот: случайно вызвать «фабрику» повторно и потерять накопленные данные.

### ⚠️ Классическая ловушка: `var` в цикле

```js
for (var i = 1; i <= 3; i++) {
  setTimeout(() => console.log(i), 100)
}
// выведет 4 4 4 (!)

for (let i = 1; i <= 3; i++) {
  setTimeout(() => console.log(i), 100)
}
// выведет 1 2 3
```

С `var` переменная `i` **одна на весь цикл**, и все три функции видят её финальное значение. `let` создаёт новую `i` на **каждом шаге** цикла. Это ещё одна причина не писать `var`.

## Часть 3. Объекты

### Создание и доступ к свойствам

```js
const book = {
  title: 'Мастер и Маргарита',
  year: 1967,
  'is read': true,     // ключ с пробелом — только в кавычках
}

book.title        // через точку
book['title']     // через квадратные скобки — то же самое
book['is read']   // ключ с пробелом — только через скобки
```

### ⚠️ Точка или скобки

Скобки нужны, когда **имя свойства лежит в переменной**:

```js
const field = 'year'
book.field     // undefined — ищет свойство с именем "field"!
book[field]    // 1967 — берёт значение переменной field
```

Это одна из самых частых ошибок при переходе с других языков.

### Добавление, изменение, удаление

```js
book.author = 'Булгаков'  // добавить
book.year = 1966          // изменить
delete book['is read']    // удалить
```

### ⚠️ `const` не замораживает объект

`const` запрещает только **присвоить переменной другой объект**. Менять свойства можно:

```js
const point = { x: 1 }
point.x = 5      // ✓ можно
point = { x: 5 } // ✗ TypeError
```

### Сокращения

```js
const name = 'Аня'
const age = 25

// свойство с тем же именем, что у переменной
const user = { name, age } // то же, что { name: name, age: age }

// вычисляемый ключ
const key = 'role'
const admin = { [key]: 'admin' } // { role: 'admin' }

// метод
const dog = {
  bark() { return 'Гав' }, // то же, что bark: function () { ... }
}
```

### Проверка наличия свойства

```js
const settings = { sound: undefined }

settings.sound === undefined // true
settings.music === undefined // тоже true!

'sound' in settings  // true — свойство есть, просто значение undefined
'music' in settings  // false — свойства нет совсем
```

⚠️ Сравнение с `undefined` не отличает «свойства нет» от «свойство есть, но равно `undefined`». Обычно это неважно, но `in` точнее.

### Перебор свойств

```js
const prices = { tea: 100, coffee: 150 }

for (const key in prices) {
  console.log(key, prices[key])  // tea 100, coffee 150
}

Object.keys(prices)    // ['tea', 'coffee']
Object.values(prices)  // [100, 150]
Object.entries(prices) // [['tea', 100], ['coffee', 150]]
```

### ⚠️ Порядок свойств

Строковые ключи идут в порядке добавления, а ключи-**числа** сортируются по возрастанию:

```js
const codes = { '49': 'Германия', '7': 'Россия', '1': 'США' }
Object.keys(codes) // ['1', '7', '49'] — отсортировано!
```

### ⚠️ Ключи всегда строки

```js
const obj = { 1: 'один' }
obj['1'] // 'один' — число 1 превратилось в строку '1'
```

## Часть 4. Ссылки и копии

### Примитивы копируются, объекты — нет

**Примитивы** (строки, числа, булевы, `null`, `undefined`) при присваивании **копируются**:

```js
let a = 'кот'
let b = a
b = 'пёс'
a // 'кот'
```

**Объекты** (включая массивы и функции) хранятся **по ссылке**. В переменной лежит не сам объект, а его «адрес»:

```js
const original = { score: 10 }
const alias = original     // скопирован адрес, объект один
alias.score = 99
original.score             // 99
```

```
original ──┐
           ├──► { score: 99 }
alias ─────┘
```

### Сравнение объектов

`===` сравнивает **адреса**, а не содержимое:

```js
const x = { a: 1 }
const y = { a: 1 }
const z = x

x === y // false — два разных объекта с одинаковым содержимым
x === z // true — один и тот же объект
```

⚠️ Поэтому `[] === []` и `{} === {}` дают `false`.

### ⚠️ Объект, переданный в функцию, можно испортить

В функцию передаётся **ссылка**, так что функция может изменить оригинал:

```js
function birthday(person) {
  person.age++   // меняет объект СНАРУЖИ функции!
}

const me = { age: 25 }
birthday(me)
me.age // 26
```

Это одна из главных причин багов. Хорошее правило: **функция не должна молча менять то, что ей передали**. Пусть она возвращает новый объект. В задаче дня 3 (`mergeSettings`) это будет прямым требованием.

### Поверхностная и глубокая копия

**Поверхностная копия** — новый объект, но свойства копируются «один уровень». Если значение свойства — объект, копируется только **ссылка** на него.

```
original ──► { name: 'Аня', address: ──┐ }
                                        ├──► { city: 'Москва' }
copy ──────► { name: 'Аня', address: ──┘ }
```

Новые «коробки» верхнего уровня разные, а вложенный `address` у них **общий**. Поменяешь `copy.name` — оригинал не тронут. Поменяешь `copy.address.city` — оригинал **изменится**.

**Глубокая копия** копирует **все уровни**, и ничего общего не остаётся.

```
original ──► { name: 'Аня', address: ──► { city: 'Москва' } }
copy ──────► { name: 'Аня', address: ──► { city: 'Москва' } }   ← другой объект
```

### Способы копирования

**Поверхностная копия:**

```js
const copy1 = Object.assign({}, original)  // старый способ
const copy2 = { ...original }              // spread — подробно на дне 3
```

**Глубокая копия:**

```js
const deep1 = structuredClone(original)            // современный способ
const deep2 = JSON.parse(JSON.stringify(original)) // старый трюк
```

⚠️ Ограничения:

| Способ | Чего не умеет |
|---|---|
| `JSON.parse(JSON.stringify(...))` | теряет функции и `undefined`, превращает даты (`Date`) в строки |
| `structuredClone(...)` | не копирует функции: выбросит ошибку |

Массивы копируются так же: `[...arr]` — поверхностно, `structuredClone(arr)` — глубоко.

</details>

### Зачем это всё во Vue

Vue следит за изменениями данных. Если два компонента получили **ссылку на один объект**, изменение в одном «внезапно» отразится в другом. А на неделе 3 будет правило «не меняй props внутри компонента»: оно растёт ровно отсюда, из ссылок.

## Шпаргалка

| Тема | Запомнить |
|---|---|
| Области видимости | изнутри видно наружу, снаружи внутрь — нет |
| `var` | не использовать: игнорирует блоки, поднимается |
| Замыкание | функция помнит переменные места создания |
| Каждый вызов фабрики | новая независимая память |
| Замыкание видит | текущее значение переменной, а не старое |
| `obj.key` и `obj[key]` | скобки — когда имя свойства в переменной |
| `const` объект | свойства менять можно |
| Присваивание объекта | копируется ссылка, а не объект |
| `===` у объектов | сравнивает ссылки, а не содержимое |
| Поверхностная копия | вложенные объекты остаются общими |
