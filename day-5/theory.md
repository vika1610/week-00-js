# Конспект · Неделя 0 · День 5

Асинхронность → промисы → `async` / `await` → ошибки и `try` / `catch` → `fetch` → JSON.
Почти все примеры можно запускать в консоли браузера (F12 → Console). Примеры с `fetch` лучше запускать, открыв вкладку с любым сайтом, например `https://jsonplaceholder.typicode.com`.

> ⚠️ Отмечены **подводные камни** — места, где чаще всего ошибаются.

Зачем это для Vue: любые данные с сервера (списки, посты, товары) загружаются асинхронно. Состояния «Загрузка…» и «Ошибка» будут почти в каждом проекте. На неделе 4 ты напишешь свой `useFetch`, и он будет построен на этом дне.

## Часть 1. Синхронный и асинхронный код

### Синхронный код — строго по очереди

```js
console.log('1')
console.log('2')
console.log('3')
// 1, 2, 3
```

Каждая строка ждёт, пока выполнится предыдущая.

### Проблема: долгие операции

Запрос на сервер может идти секунду, а может и пять. Если бы JS просто **ждал** ответа, страница бы «зависла»: кнопки не нажимаются, ничего не прокручивается.

Поэтому долгие операции в JS **асинхронные**: «начни это делать, а когда закончишь — сообщи. Я пока займусь другим».

### `setTimeout` — самый простой пример

```js
console.log('1')
setTimeout(() => console.log('2'), 1000)
console.log('3')
// 1, 3, а через секунду — 2
```

`setTimeout` не останавливает код. Он **записывает** функцию «на потом» и сразу отпускает дальше.

### ⚠️ Даже ноль миллисекунд — это «потом»

```js
console.log('1')
setTimeout(() => console.log('2'), 0)
console.log('3')
// 1, 3, 2 — всё равно 2 в конце!
```

JS сначала доделывает весь текущий код, и только потом берёт отложенные задачи. Как официант: сначала принимает весь заказ за столиком и только потом идёт на кухню проверять, что готово.

## Часть 2. Промисы

### Что такое промис

**Промис** (Promise, «обещание») — объект, который означает «результат будет **позже**». Как талончик в кафе: еды ещё нет, но талончик уже у тебя, и по нему ты её получишь.

У промиса три состояния:

| Состояние | Значит |
|---|---|
| `pending` (ожидание) | результата ещё нет |
| `fulfilled` (выполнен) | готово, есть результат |
| `rejected` (отклонён) | случилась ошибка |

Из `pending` промис переходит **один раз** либо в `fulfilled`, либо в `rejected`, и дальше уже не меняется.

### Как получить результат: `.then`, `.catch`, `.finally`

```js
fetch('https://jsonplaceholder.typicode.com/todos/1')
  .then((response) => response.json())
  .then((todo) => console.log(todo.title))
  .catch((error) => console.log('Ошибка:', error.message))
  .finally(() => console.log('Готово'))
```

- `.then(fn)` — «когда выполнится, вызови `fn` с результатом»;
- `.catch(fn)` — «если ошибка, вызови `fn` с ошибкой»;
- `.finally(fn)` — «в любом случае, после успеха или ошибки».

`.then` тоже возвращает промис, поэтому их можно выстраивать **цепочкой**: результат одного `.then` попадает в следующий.

### Как создать свой промис

Редко нужно, но полезно понимать:

```js
const coinFlip = new Promise((resolve, reject) => {
  setTimeout(() => {
    if (Math.random() > 0.5) {
      resolve('Орёл')                 // успех — с результатом
    } else {
      reject(new Error('Решка'))      // ошибка
    }
  }, 1000)
})

coinFlip
  .then((result) => console.log('Выпало:', result))
  .catch((error) => console.log('Не повезло:', error.message))
```

- `resolve(значение)` — перевести промис в «выполнен»;
- `reject(ошибка)` — перевести в «отклонён».

Функция внутри `new Promise` запускается **сразу**, а `resolve` или `reject` ты вызываешь, когда работа закончена.

### ⚠️ Промис — это не результат

```js
const result = fetch('https://jsonplaceholder.typicode.com/todos/1')
console.log(result) // Promise {<pending>} — талончик, а не еда!
```

Если в консоли видишь `Promise {<pending>}` там, где ждала данные, значит результат промиса не дождались. Чаще всего забыли `await` (о нём ниже).

## Часть 3. `async` / `await`

Цепочки `.then` работают, но читаются тяжело. `async` / `await` позволяют писать асинхронный код **так, будто он обычный**, сверху вниз.

### Синтаксис

```js
async function loadTodo() {
  const response = await fetch('https://jsonplaceholder.typicode.com/todos/1')
  const todo = await response.json()
  return todo.title
}
```

- `async` перед функцией означает «внутри будет `await`»;
- `await промис` — «подожди, пока промис выполнится, и дай мне результат».

Сравни с версией на `.then` из части 2: делает то же самое, а читается как обычный рецепт.

Стрелочная функция тоже может быть асинхронной:

```js
const loadTodo = async () => { /* ... */ }
```

### ⚠️ `async`-функция ВСЕГДА возвращает промис

Это ответ на один из вопросов «Проверь себя» недели:

```js
async function getNumber() {
  return 42
}

getNumber()           // Promise {<fulfilled>: 42} — не 42!
await getNumber()     // 42
getNumber().then((n) => console.log(n)) // 42
```

Даже если внутри `return 42`, снаружи получишь **промис**, который выполнится с `42`. Чтобы достать число, нужен `await` (или `.then`).

### ⚠️ `await` работает только внутри `async`

```js
function broken() {
  const data = await fetch('...') // ✗ SyntaxError
}
```

Исключение — верхний уровень модуля и консоль браузера: там `await` можно писать без `async`.

### ⚠️ Забытый `await`

```js
async function loadTodo() {
  const response = fetch('...')       // забыли await
  const todo = await response.json()  // ✗ TypeError: response.json is not a function
}
```

В `response` лежит промис, а не ответ сервера, и метода `.json` у промиса нет. Если видишь странную ошибку про «is not a function» или `undefined` рядом с асинхронным кодом, первым делом проверь, везде ли стоит `await`.

### `await` останавливает только свою функцию

```js
async function slow() {
  console.log('A')
  await new Promise((resolve) => setTimeout(resolve, 1000))
  console.log('B')
}

slow()
console.log('C')
// A, C, а через секунду — B
```

`await` ставит на паузу **только** `slow`. Остальной код идёт дальше: вот почему страница не зависает.

### Последовательно или параллельно

```js
// по очереди: сначала первый, потом второй — дольше
const a = await fetch(url1)
const b = await fetch(url2)

// одновременно — быстрее
const [c, d] = await Promise.all([fetch(url1), fetch(url2)])
```

`Promise.all` ждёт, пока выполнятся **все** промисы из массива, и возвращает массив результатов. Если хотя бы один упадёт, упадёт и `Promise.all`. Подробно понадобится на неделе 5 (блог: пост и комментарии одновременно).

## Часть 4. Ошибки: `throw`, `try` / `catch` / `finally`

### Выбросить ошибку

```js
function divide(a, b) {
  if (b === 0) {
    throw new Error('Делить на ноль нельзя')
  }
  return a / b
}
```

`throw` **немедленно** прекращает выполнение функции, как `return`, только «аварийно». Ошибка летит вверх, пока её кто-нибудь не поймает. Если никто не поймал, она окажется красной строкой в консоли.

Всегда выбрасывай объект `new Error('текст')`, а не просто строку: у объекта ошибки есть `message` и место, где она случилась.

### Поймать ошибку

```js
try {
  divide(10, 0)
  console.log('этой строки не будет')
} catch (error) {
  console.log('Поймали:', error.message) // 'Поймали: Делить на ноль нельзя'
} finally {
  console.log('Выполнится в любом случае')
}
```

- `try` — «попробуй выполнить»;
- `catch (error)` — «если в `try` что-то сломалось, приходи сюда». Код в `try` после ошибки **не выполняется**;
- `finally` — «в конце, при любом исходе». Удобное место, чтобы выключить «Загрузка…».

### `try` / `catch` с `async` / `await`

С `await` ошибки промисов ловятся обычным `try` / `catch`:

```js
async function loadPost(id) {
  try {
    const response = await fetch(`https://jsonplaceholder.typicode.com/posts/${id}`)
    const post = await response.json()
    console.log(post.title)
  } catch (error) {
    console.log('Не получилось:', error.message)
  }
}
```

### ⚠️ `try` / `catch` без `await` ничего не поймает

```js
try {
  fetch('https://нет-такого-сайта.рф') // без await
} catch (error) {
  console.log('сюда не попадём') // промис упадёт позже, когда try уже закончился
}
```

Ошибка промиса случается **потом**, а `try` проверяет только то, что происходит **сейчас**. С `await` код ждёт результата внутри `try`, поэтому ошибка ловится.

### ⚠️ Не глотай ошибки молча

```js
try {
  // ...
} catch (error) {
  // пусто — ошибка исчезла бесследно
}
```

Пользователь увидит вечное «Загрузка…», а ты не поймёшь почему. Минимум — показать сообщение пользователю или хотя бы `console.error(error)`.

## Часть 5. `fetch` — запросы на сервер

### Простейший запрос

```js
const response = await fetch('https://jsonplaceholder.typicode.com/posts/1')
```

`fetch` возвращает промис с объектом **`Response`**, то есть ответом сервера. Это ещё **не данные**, а «конверт», в котором они лежат.

### Что есть в ответе

```js
response.ok      // true, если статус 200–299 (всё хорошо)
response.status  // 200, 404, 500…
await response.json() // данные: разобрать тело ответа как JSON
```

⚠️ `response.json()` — тоже **асинхронный** метод, ему тоже нужен `await`. Получается два `await` подряд: первый ждёт ответ, второй — тело ответа.

### Коды ответа

| Код | Значит |
|---|---|
| 200 | всё хорошо |
| 404 | не найдено (неправильный адрес, нет такого поста) |
| 500 | ошибка на сервере |

### ⚠️⚠️ `fetch` НЕ считает 404 и 500 ошибкой

Самая коварная особенность `fetch`:

```js
const response = await fetch('https://jsonplaceholder.typicode.com/postsss')
response.ok     // false
response.status // 404
// но никакой ошибки не выброшено! catch не сработает
```

С точки зрения `fetch` всё прошло успешно: сервер ответил, пусть и «не нашёл». Промис отклоняется (`rejected`), только если **ответа не было вообще**: нет интернета, неправильное имя сайта, сервер недоступен.

Поэтому `response.ok` нужно проверять **самой**, и если там `false`, выбросить ошибку через `throw`. Тогда и 404, и обрыв сети попадут в один и тот же `catch`.

| Ситуация | Промис `fetch` | `response.ok` |
|---|---|---|
| всё хорошо (200) | выполнен | `true` |
| не найдено (404), ошибка сервера (500) | **выполнен** ⚠️ | `false` |
| нет сети, сайт недоступен | отклонён | — ответа нет |

### Три состояния экрана

Любая загрузка данных на странице — это три состояния:

```
«Загрузка…»  ──►  данные пришли  ──►  показать список
             └─►  ошибка         ──►  показать «Ошибка: …»
```

Обычный порядок:
1. **сразу** показать «Загрузка…», ещё **до** первого `await`, иначе пользователь какое-то время видит пустоту;
2. в `try`: загрузить и показать данные;
3. в `catch`: показать понятное сообщение об ошибке.

Во Vue это будут три переменные: `data`, `loading`, `error`. Ты их встретишь на неделях 4 и 5.

## Часть 6. JSON

### Что это

**JSON** — текстовый формат для обмена данными. Выглядит почти как объекты JS:

```json
{
  "id": 1,
  "title": "Купить хлеб",
  "done": false,
  "tags": ["дом", "еда"]
}
```

Отличия от объекта JS:
- ключи **всегда** в двойных кавычках `"..."`;
- строки — **только** в двойных кавычках, одинарные нельзя;
- нет функций, `undefined`, комментариев;
- нет запятой после последнего элемента.

Сервер присылает данные в JSON, а `localStorage` (неделя 2) хранит только строки, так что JSON нужен постоянно.

### Объект → строка: `JSON.stringify`

```js
const todo = { id: 1, title: 'Хлеб', done: false }

JSON.stringify(todo)
// '{"id":1,"title":"Хлеб","done":false}' — это СТРОКА

JSON.stringify(todo, null, 2) // с отступами — удобно читать
```

### Строка → объект: `JSON.parse`

```js
const text = '{"id":1,"title":"Хлеб"}'
const obj = JSON.parse(text)
obj.title // 'Хлеб'
```

### ⚠️ `JSON.parse` выбрасывает ошибку на некорректной строке

```js
JSON.parse('{abc}')        // ✗ SyntaxError
JSON.parse("{'a': 1}")     // ✗ SyntaxError — одинарные кавычки нельзя
JSON.parse('')             // ✗ SyntaxError — пустая строка тоже ошибка
```

Данные из внешнего мира (сервер, `localStorage`, ввод пользователя) могут оказаться испорченными. Вспомни часть 4: как сделать, чтобы на такой строке программа не упала?

### ⚠️ Что теряется в `JSON.stringify`

```js
JSON.stringify({
  name: 'Аня',
  hi() {},              // функция — пропадёт
  age: undefined,       // undefined — пропадёт
  born: new Date(2000, 0, 1), // дата — превратится в строку
})
// '{"name":"Аня","born":"1999-12-31T21:00:00.000Z"}' — точное время зависит от часового пояса
```

Это тот же «старый трюк» глубокого копирования из дня 2, и вот почему у него ограничения.

## Шпаргалка

| Тема | Запомнить |
|---|---|
| `setTimeout(fn, 0)` | всё равно «потом», после текущего кода |
| Промис | «результат будет позже»: `pending` → `fulfilled` / `rejected` |
| `Promise {<pending>}` в консоли | забыли `await` |
| `async`-функция | **всегда** возвращает промис |
| `await` | только внутри `async` (и на верхнем уровне модуля) |
| `await` | ставит на паузу только свою функцию |
| `throw new Error('…')` | выбросить ошибку, функция прерывается |
| `try` / `catch` / `finally` | поймать ошибку; `finally` — при любом исходе |
| `try` без `await` | ошибку промиса не поймает |
| `fetch` | возвращает `Response`, а не данные |
| `response.json()` | тоже нужен `await` |
| 404 / 500 | `fetch` **не** выбрасывает ошибку — проверяй `response.ok` |
| «Загрузка…» | показывать до первого `await` |
| `JSON.stringify` / `JSON.parse` | объект → строка / строка → объект |
| `JSON.parse` на плохой строке | выбрасывает ошибку |
