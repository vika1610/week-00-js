## Часть 1. Модули: `import` и `export`

### Зачем нужны модули

Без модулей весь код живёт в одном огромном файле, или во многих `<script>`, которые видят переменные друг друга и мешают друг другу.

**Модуль** — это просто файл. У каждого модуля **своя область видимости**: переменные внутри файла не видны снаружи, пока ты сама их не **экспортируешь**.

```
math.js      ← модуль: что-то экспортирует
main.js      ← модуль: что-то импортирует из math.js
```

### Именованный экспорт

Пишешь `export` перед тем, что хочешь отдать наружу:

```js
// math.js
export const PI = 3.14

export function circleArea(r) {
  return PI * r * r
}

function secretHelper() {}  // без export — снаружи не видно
```

Импорт — **в фигурных скобках**, имена должны совпадать:

```js
// main.js
import { PI, circleArea } from './math.js'

circleArea(2) // 12.56
```

Можно переименовать при импорте:

```js
import { circleArea as area } from './math.js'
```

Или забрать всё сразу в объект:

```js
import * as math from './math.js'
math.circleArea(2)
```

### Экспорт по умолчанию (`default`)

Один на файл. Обычно так экспортируют «главное», ради чего файл существует:

```js
// Greeter.js
export default function greet(name) {
  return `Привет, ${name}`
}
```

Импорт — **без фигурных скобок**, имя можно придумать любое:

```js
import greet from './Greeter.js'
import sayHello from './Greeter.js' // то же самое, просто другое имя
```

Во Vue так импортируют компоненты: `import ProductCard from './ProductCard.vue'`.

### ⚠️ Фигурные скобки или нет

| Как экспортировано | Как импортировать |
|---|---|
| `export function f` | `import { f } from ...` — со скобками, имя то же |
| `export default function f` | `import f from ...` — без скобок, имя любое |

Перепутаешь — получишь ошибку вида *does not provide an export named …* или `undefined`.

### ⚠️ Путь к файлу

В браузере путь пишется **полностью**:

```js
import { f } from './utils.js'  // ✓
import { f } from 'utils.js'    // ✗ без ./ браузер ищет пакет, а не файл
import { f } from './utils'     // ✗ без .js файл не найдётся
```

- `./` — «в той же папке», `../` — «на папку выше».
- В проектах на Vite (неделя 3) расширение `.js` часто можно не писать: Vite найдёт файл сам. Но чистый браузер так не умеет.

### Подключение модуля на страницу

```html
<script type="module" src="./main.js"></script>
```

Без `type="module"` слова `import` и `export` вызовут ошибку *Cannot use import statement outside a module*.

### Особенности модулей

- **Строгий режим** включён автоматически: забытое `const` даёт ошибку, а не глобальную переменную (это было в дне 2).
- **Код модуля выполняется один раз**, даже если его импортируют десять файлов.
- **Модуль ждёт загрузки страницы**: скрипт `type="module"` запускается, когда HTML уже разобран. Поэтому элементы страницы в нём уже доступны.
- `import` пишется **в начале файла**, вне функций и `if`.

### ⚠️ Модули не работают при открытии файла двойным кликом

Если открыть `index.html` двойным кликом (адрес вида `file:///C:/...`), браузер **заблокирует** загрузку модулей из соображений безопасности. В консоли будет ошибка про CORS.

Нужен локальный сервер, поэтому в задаче есть команда `npm run serve:day4`.

## Часть 2. `this`

### Что такое `this`

`this` — специальное слово внутри функции. Оно означает **«объект, у которого вызвали метод»**.

```js
const cat = {
  name: 'Барсик',
  introduce() {
    return `Я ${this.name}`
  },
}

cat.introduce() // 'Я Барсик' — this = cat, потому что вызвали cat.introduce()
```

Зачем писать `this.name`, а не `cat.name`? Чтобы один и тот же метод работал для **любого** объекта:

```js
const dog = { name: 'Шарик', introduce: cat.introduce }
dog.introduce() // 'Я Шарик' — тот же метод, но this = dog
```

### Главное правило

> **`this` определяется в момент вызова** — по тому, что стоит **перед точкой**.

```js
cat.introduce()   // перед точкой cat → this = cat
dog.introduce()   // перед точкой dog → this = dog
```

### ⚠️ Потерянный `this`

Если взять метод **без вызова** и вызвать отдельно, точки перед ним нет, и `this` теряется:

```js
const fn = cat.introduce
fn() // ✗ TypeError: Cannot read properties of undefined (reading 'name')
```

То же происходит, когда метод передают куда-то **как функцию**:

```js
setTimeout(cat.introduce, 1000) // ✗ this потерян — setTimeout вызывает fn() без точки
```

Это одна из самых частых ошибок в JS. Как спасти — ниже.

### Стрелочные функции и `this`

У стрелочных функций **нет своего `this`**. Они берут `this` из внешнего кода, того места, где их **написали**:

```js
const timer = {
  seconds: 0,
  start() {
    setInterval(() => {
      this.seconds++   // ✓ стрелка взяла this из start(), а там this = timer
    }, 1000)
  },
}
```

Если бы внутри `setInterval` была обычная `function`, её `this` был бы потерян.

Один из способов спасти `this` из предыдущего раздела:

```js
setTimeout(() => cat.introduce(), 1000) // ✓ внутри стрелки обычный вызов с точкой
```

### ⚠️ Стрелка как метод объекта — плохая идея

```js
const cat = {
  name: 'Барсик',
  introduce: () => `Я ${this.name}`, // ✗ this — не cat, а внешний (undefined)
}
```

Правило: **методы объектов — обычные функции** (короткая запись `introduce() {}`), **функции внутри методов** — стрелки.

### ⚠️ Забытый `this.`

```js
const cat = {
  name: 'Барсик',
  introduce() {
    return `Я ${name}` // ✗ ищет переменную name, а не свойство объекта
  },
}
```

Внутри метода свойства объекта доступны **только** через `this.`.

> Хорошая новость: в `<script setup>` во Vue `this` почти не используется. Но понимать его нужно: он встречается в чужом коде, в классах и в старом стиле Vue (Options API).

## Часть 3. Классы

### Зачем

Класс — это **шаблон** для создания однотипных объектов. Как форма для печенья: форма одна, печенья много, у каждого своя начинка.

### Синтаксис

```js
class Pet {
  constructor(name, age) {
    this.name = name   // поле объекта
    this.age = age
  }

  describe() {         // метод
    return `${this.name}, ${this.age} г.`
  }

  birthday() {
    this.age++         // метод может менять поля
  }
}
```

Создание объектов — через `new`:

```js
const rex = new Pet('Рекс', 3)
const tom = new Pet('Том', 5)

rex.describe() // 'Рекс, 3 г.'
rex.birthday()
rex.age        // 4
tom.age        // 5 — у каждого объекта свои данные
```

### Что делает `new`

1. Создаёт **новый пустой объект**.
2. Вызывает `constructor`, где `this` — этот новый объект.
3. Возвращает объект.

Поэтому в конструкторе пишут `this.name = name`: «запиши в новый объект свойство `name`».

### Проверка, из какого класса объект

```js
rex instanceof Pet // true
```

### Наследование (обзор)

Класс можно «расширить»: взять всё от родителя и добавить своё.

```js
class Dog extends Pet {
  bark() {
    return `${this.name}: Гав!`
  }
}

const sharik = new Dog('Шарик', 2)
sharik.describe() // 'Шарик, 2 г.' — метод от Pet
sharik.bark()     // 'Шарик: Гав!' — свой метод
```

Пока достаточно знать, что так можно.

### ⚠️ Подводные камни классов

**1. Забытый `new`:**
```js
const x = Pet('Рекс', 3) // ✗ TypeError: Class constructor Pet cannot be invoked without 'new'
```

**2. Методы в классе пишутся без запятых** (в отличие от объекта):
```js
class A {
  first() {}   // без запятой!
  second() {}
}
```

**3. Свойство без `this` — это не свойство:**
```js
constructor(name) {
  name = name        // ✗ ничего не сохранится
  this.name = name   // ✓
}
```

**4. Класс нельзя использовать до объявления** (как `let` / `const`, «мёртвая зона» из дня 2).

**5. Потерянный `this` работает и с методами классов:**
```js
const fn = rex.describe
fn() // ✗ this потерян
```

### Классы и объекты-фабрики

В дне 2 ты делала `makeCounter` — функцию, которая возвращает объект с методами. Класс решает похожую задачу, но по-другому:

| | Фабрика (день 2) | Класс |
|---|---|---|
| Создание | `makeCounter()` | `new Counter()` |
| Данные | спрятаны в замыкании | лежат в полях, доступны через `this` и снаружи |
| `this` | не нужен | нужен везде |

Во Vue (композаблы, Pinia) чаще используется подход с функциями и замыканиями. Классы встречаются реже, но понимать их надо.

## Часть 4. События DOM

### Что такое DOM

**DOM** — это страница глазами JavaScript: дерево объектов, где каждый тег — объект. Через эти объекты можно читать и менять страницу.

### Найти элемент

```html
<h1 id="title">Привет</h1>
<p class="note">Заметка</p>
```

```js
document.getElementById('title')        // по id — без #
document.querySelector('#title')        // по CSS-селектору — с #
document.querySelector('.note')         // первый элемент с классом note
document.querySelectorAll('.note')      // все элементы с классом note
```

⚠️ Не перепутай: в `getElementById` пишется просто `'title'`, а в `querySelector` — `'#title'`.

### ⚠️ Если элемент не найден — `null`

```js
const el = document.querySelector('#nope') // null
el.textContent = 'текст' // ✗ TypeError: Cannot set properties of null
```

Если видишь в консоли *Cannot … of null*, первым делом проверь:
- правильно ли написан id или селектор (опечатка, лишний `#`);
- есть ли такой элемент в HTML;
- не запускается ли скрипт раньше, чем появился элемент. С `type="module"` это не грозит.

### Менять содержимое

```js
const title = document.getElementById('title')

title.textContent             // 'Привет' — прочитать текст
title.textContent = 'Пока'    // заменить текст
title.style.color = 'red'     // поменять стиль
title.classList.add('big')    // добавить класс
title.classList.toggle('big') // добавить, если нет; убрать, если есть
```

### ⚠️ `textContent` или `innerHTML`

```js
el.textContent = '<b>жирный</b>' // покажет текст буквально: <b>жирный</b>
el.innerHTML = '<b>жирный</b>'   // покажет жирное слово
```

`innerHTML` разбирает строку как HTML. Если вставить туда текст, который ввёл пользователь, он может подсунуть на страницу свой код. Правило: **для текста — `textContent`**, `innerHTML` — только для своей, проверенной разметки.

### Подписаться на событие

```js
const button = document.querySelector('#like')
let likes = 0

button.addEventListener('click', () => {
  likes++
  button.textContent = `❤️ ${likes}`
})
```

- первый аргумент — **название события**: `'click'`, `'input'`, `'submit'`, `'keydown'`, `'mouseover'`…
- второй — **функция-обработчик**: её вызовут при каждом событии.

Обрати внимание: обработчик меняет переменную `likes`, объявленную снаружи. Это замыкание из дня 2!

### ⚠️⚠️ Самая частая ошибка: вызов вместо передачи

```js
function sayHi() { console.log('Привет') }

button.addEventListener('click', sayHi)   // ✓ передали функцию — вызовут при клике
button.addEventListener('click', sayHi()) // ✗ вызвали СРАЗУ, передали результат (undefined)
```

Со скобками функция выполняется **сразу при загрузке**, а на клик ничего не происходит.

Если в обработчик нужно передать аргумент, оберни вызов в стрелку:

```js
button.addEventListener('click', () => sayHello('Аня')) // ✓
```

### ⚠️ Название события без `on`

```js
button.addEventListener('click', ...)   // ✓
button.addEventListener('onclick', ...) // ✗ такого события нет — тихо ничего не произойдёт
```

### Объект события

Обработчик получает аргумент с информацией о событии:

```js
button.addEventListener('click', (event) => {
  event.target    // элемент, по которому кликнули
  event.type      // 'click'
})

input.addEventListener('input', (event) => {
  event.target.value // текущий текст в поле
})
```

### `this` в обработчике

В обработчике-**функции** (не стрелке) `this` — это элемент, на котором висит обработчик:

```js
button.addEventListener('click', function () {
  this.textContent = 'Нажато' // this = button
})
```

Со **стрелкой** `this` будет внешним. Поэтому надёжнее обращаться к элементу через переменную (`button`) или `event.target`, а не через `this`.

### Отписаться от события

```js
function onClick() { /* ... */ }

button.addEventListener('click', onClick)
button.removeEventListener('click', onClick) // нужна ТА ЖЕ функция
```

⚠️ Стрелку, написанную прямо внутри `addEventListener`, потом не отпишешь: на неё нет ссылки. Во Vue это станет важно на неделе 2, где таймер нужно останавливать при уходе со страницы.

### ⚠️ Обработчик, добавленный дважды, срабатывает дважды

Если вызвать `addEventListener` два раза, один клик запустит обе функции. Частая причина «почему счётчик прибавляет по 2».

### Как это будет выглядеть во Vue

Для сравнения, чтобы было видно, к чему мы идём:

```js
// чистый JS
button.addEventListener('click', () => { likes++ })
```

```html
<!-- Vue (неделя 1–2) -->
<button @click="likes++">❤️ {{ likes }}</button>
```

Vue сам находит элемент, подписывается на событие и обновляет текст. Но внутри это тот же `addEventListener`.

## Шпаргалка

| Тема | Запомнить |
|---|---|
| `export function f` | импорт `import { f }` — со скобками, имя то же |
| `export default` | импорт без скобок, имя любое; один на файл |
| Путь импорта в браузере | `./файл.js` — с `./` и с `.js` |
| `type="module"` | без него `import` не работает; нужен сервер, не `file://` |
| `this` | объект перед точкой **в момент вызова** |
| Стрелки | своего `this` нет, берут внешний |
| Методы объекта | обычные функции, не стрелки |
| Класс | `constructor` + методы без запятых; создавать через `new` |
| Поля класса | только через `this.поле` |
| `querySelector` | ничего не нашёл → `null` |
| `textContent` | безопасно для текста; `innerHTML` — для своей разметки |
| `addEventListener('click', fn)` | передать `fn`, а **не** `fn()`; событие без `on` |
